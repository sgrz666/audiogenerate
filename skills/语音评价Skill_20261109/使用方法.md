# 把评价规范交给音频理解模型

这个包用于评价已经生成的中文语音，不负责命题或生成音频。`speech-synthesis-audio-review/SKILL.md` 是完整规则，包含评分口径和输出字段。

## 聊天上传

一次准备三样材料：

1. `SKILL.md`：评价规范。
2. **实际待评音频**：例如 `demo_001_v1.wav`。本包未附带真实音频，也没有已有模型评价结果。
3. **原文和要求**：直接在聊天里写，或复制 `assets/request.example.json`，修改音频名、原文、音色和播报要求后上传。

可直接复制以下请求：

> 请按附件 SKILL.md 评价附件音频。原文及目标要求见 request.json，音频文件名与 audio_file 一一对应。请先确认可以实际听取音频，然后输出规范要求的 JSON。不能确定的读音、音色或时间位置要如实注明，不要根据文字猜测音频表现。

如果平台不能读取 Markdown 附件，把 `SKILL.md` 的正文直接粘贴到消息中。只有当模型及当前输入通道确实支持音频理解时，这种方式才有效；上传成功也不等于模型一定能访问到文件。

如果只有原文和目标、没有实际音频，规范要求模型返回 `unavailable`，不产生试听分数。

## 接口调用

支持 system/developer 指令的接口，可把 `SKILL.md` 正文放入该角色；把任务 JSON 与实际音频放入 user 输入。具体音频传输使用所选服务的正式文件、音频数据或可访问地址机制。本包不预设服务商，不包含 API 密钥或联网调用脚本。

`assets/review.schema.json` 是输出 JSON 的结构约束，可用于支持 JSON Schema 的工具或本地检查。不同服务对 Schema 支持程度可能不同，不能直接假设所有服务接受同一套严格输出参数。

## 先怎样试

先挑少量已听过的片段，包括正常样例、明显问题和容易误判的样例。保持文件名中不透露“好/坏”或模型名称，给同样的原文和要求。把输出问题和人工判断逐条比对，再决定是否批量使用。

第一轮重点看模型是否能找到位置和具体表现，不只看分数。原有音频中的自然音色特点、短暂发音闭塞，不应直接被归因为合成伪音。没有测量数据时，不使用模型猜出的数值语速或噪声指标。

输出的 `usable` 表示模型初筛建议可用，`revise` 表示有明确修改依据，`human_review` 表示需要核对，`unavailable` 表示没有获得可评价的音频。它们不是正式验收结论。
